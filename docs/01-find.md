# Find

**Goal:** Locate a real opportunity before you build.

## Outputs

- One-sentence audience
- One-sentence job-to-be-done / pain
- Coping alternatives (how they solve it today)
- Hypothesis of a better path
- Labels: what is FACT vs HYPOTHESIS

## Steps

### 1. Audience (narrow)
Bad: “developers”  
Better: “solo developers shipping side projects with AI coding agents”

Write: *I help ____ who struggle with ____.*

### 2. Pain (observable)
Prefer pains you can hear in forums, Discord, coworker rants, your own calendar.

Ask:
- What did they try last?
- What did they pay for (money or time)?
- What do they complain about twice?

### 3. Coping map
List 3 current workarounds. Ugly counts (spreadsheets, copy-paste, hiring freelancers).

### 4. Opportunity lens (AI economy)
Useful lenses — pick one, don’t boil the ocean:

| Lens | Question |
| --- | --- |
| Agentic workflow | Where does a human still babysit the agent? |
| Tool confusion | Where do people pick tools by hype, not fit? |
| Monetization gap | Where do builders create value but never capture it? |
| Simplification | What takes a thread of 40 tools to explain today? |

### 5. Hypothesis
One line: *If we provide ____ for ____, they will ____ because ____.*

Mark unknowns. If everything is labeled FACT, you’re lying to yourself.

## Anti-patterns

- Building because a model suggested it
- “AI for X” with no coping map
- Audience = everyone with a GitHub account

## Exit criteria

You can explain the opportunity in &lt;60 seconds without naming a tech stack.
